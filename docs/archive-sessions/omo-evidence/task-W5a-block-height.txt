LAYOUT-P1 / BLOCK-OVERLAP — expanded-tier block height measurement
====================================================================
Date: 2026-05-29
Subject: expanded-tier MODIFIER block (tallest variant: 5-fader ParamStrip +
         Meter + Spectrum) — the block that overlaps on BRASS_4Horns.

ROOT CAUSE (see .omo/audit/layout-finding.md):
  At the expanded zoom tier (react-flow zoom > 0.8) each block additionally
  renders BlockEmbed. For a modifier block that is ParamStrip(5) + Meter +
  Spectrum, making the block far taller than the ~140px minimum vertical gap
  in BRASS_4Horns' legacy saved positions (478-338=140) — so vertically
  adjacent expanded blocks overlap. Width (w-48, 192px) is constant and has
  headroom; the overlap is height-driven and vertical-only, only at the
  expanded tier. Saved positions are correct user data and are NOT mutated.

TARGET (necessary condition):
  expanded modifier block layout height <= ~125px
  (clears the ~140px min legacy column gap with margin)

MEASUREMENT METHOD:
  Story:   webview/src/components/canvas/BlockExpandedHeight.stories.tsx
           (Canvas/BlockExpandedHeight → ExpandedModifier; forces
            useGraphStore zoomTier="expanded", seeds 5 fader values, fitView
            disabled so the viewport is zoom 1).
  Script:  webview/.storybook/measure-block.mjs (Playwright/chromium).
  Harness: Storybook dev server on :6006 (uses vite.config.ts, which includes
           @tailwindcss/vite — so utility classes ARE applied and the height
           is production-real). The vitest browser project was NOT usable for
           the measurement: it has no Tailwind processor, so the block renders
           unstyled (display:block, faders stack) — confirmed and rejected.
  Metric:  offsetHeight of the Block root element
           (`.react-flow__node` > firstElementChild). offsetHeight is the
           UNSCALED layout height; with fitView off the viewport is zoom 1.
           A `display:flex` guard rejects any unstyled (Tailwind-absent) read.

RESULTS (raw script output):
  BEFORE:  MEASURE before display=flex height=226
  AFTER:   MEASURE after  display=flex height=104

  BEFORE: 226 px  (overlaps the 140px column gap by 86px → BLOCK-OVERLAP)
  AFTER:  104 px  (<= 125px target; clears the 140px gap by 36px)
  Reduction: 122 px (54%). display=flex confirms Tailwind utilities applied
             in both reads, so the numbers are production-real and comparable.

FIX (compress expanded block height; positions untouched; no C++):
  webview/src/components/canvas/Block.tsx
    - Gate the redundant body section (Signal Processing / Routing placeholder
      + latency/cpu rows) behind `zoomTier !== "expanded"`. At the expanded
      tier the BlockEmbed already shows real faders/meter, so the placeholder
      body was pure redundant vertical height. Highest-leverage cut and a pure
      React conditional (CSS-independent). Body still shows at standard tier.
  webview/src/components/canvas/BlockEmbed.tsx
    - MiniFader: hover value tooltip moved OUT of the flex flow
      (absolute `-top-2.5`) so it no longer adds ~11px permanent height to
      every expanded block; fader track height 32 -> 20.
    - ParamStripEmbed: vertical padding py-1 -> py-0.5.
    - MeterEmbed: container height 40 -> 32; MeterBar height 32 -> 24.
    - SpectrumEmbed: SVG height h 32 -> 24 (container 40 -> 32). Meter and
      Spectrum share one horizontal row, so the row height is max(meter,
      spectrum); both had to drop together to shrink the row.
    - Root embed vertical gap gap-1.5 -> gap-1.
  What the BlockEmbed still renders at the expanded tier (unchanged):
    all 5 modifier faders, the meter, and the spectrum — just compressed.
    Generator/logic embeds (fewer faders) are strictly shorter than the
    measured modifier, so 104px is the worst-case across categories.
  What the body-gate suppresses AT THE EXPANDED TIER ONLY (still shown at the
  standard tier): the category placeholder text (Signal Processing / Routing),
  the generator MiniWaveform viz, and the LATENCY + CPU readout rows. These are
  redundant at expanded zoom (the embed already shows live faders/meter) and
  were the largest source of vertical height. This is tier-scoped suppression,
  not wholesale removal. Tradeoff note: there is ~21px of headroom (104 vs the
  125 target), so one compact readout line (~12px) could be re-added at
  expanded tier if latency/CPU at max zoom is desired (lands ~116px, still
  clears the 140px gap by ~24px) — left out by default; Glen's call.
  Design language (neumorphic, info-density) preserved.
