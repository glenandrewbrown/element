### 2.3 New architectural patterns established this session

These should be **followed by future fixes** that touch the same problem space:

1. **`*Loaded` flag triad** — three Zustand fields with distinct semantics. Pick the right one:
   - `useAppStore.hostReady` — boot procedure ran to completion (incl. dev / no-host)
   - `useSessionStore.sessionLoaded` — `applySnapshot()` succeeded with non-null payload
   - `useDashboardStore.dashboardLoaded` — `loadDashboardLayoutFromHost()` ran (success or no-op)
   - All have `select*` helpers exported alongside.

2. **Bounded retry-poll** — for any "host may not be ready yet" flow. Two existing instances:
   - Plugin scan: `useJuceBridge.ts:498-514` (delays `[1500, 3000, 5000, 8000, 12000]`)
   - Session load: `useJuceBridge.ts:520-548` (delays `[500, 1500, 3000, 6000, 10000]`)
   - Plugin-editor open: `nativePluginEditor.ts` (delays `[0, 150, 400, 800, 1500]`)
   - When adding more, mirror this shape: array of delays, `if (already-good) return;` short-circuit, `logBridgeError` on catch, timer cleanup in the effect's return.

3. **Optimistic update + rollback** — for state-mutation actions where the bridge can fail. Snapshot prior state via `get()`, apply optimistic `set()`, `await` the bridge, on `false` / throw call `logBridgeError` AND `set` the snapshot back. Live in [`usePerformStore.ts`](file:///Volumes/Projects/Development_Projects/Github_Repos/element/webview/src/stores/usePerformStore.ts) for `activateScene` + `markParameterMapped`.

4. **Loose-coupling via nonce counter** — `useAppStore.refreshNonce` increments on `toggleMode` / `requestGraphStateRefresh()`; `useJuceBridge` subscribes and re-issues fetches. Avoids circular import (`useAppStore → useJuceBridge` would fail because `useJuceBridge` already imports `useAppStore`). Reuse this pattern when the store needs to trigger a bridge call without knowing the bridge.

5. **Honest empty state > fake values** — invariant carried forward from prior session, reinforced by T-P1-2, T-P1-5, T-P1-1. **If bridge data isn't available, render `0`, `"—"`, dimmed, or disabled — NEVER fabricated.** Each fake-value site I cleared has a TODO pointing to the future bridge work (`Q-VU-PER-BLOCK`, `Q-VU-INPUT`, `US-006`).

6. **Stale-fetch cancellation** — for `useEffect` fetches keyed on a changing prop, use the `let cancelled = false;` cleanup idiom + immediate state reset:
   ```typescript
   useEffect(() => {
     let cancelled = false;
     setData(emptyValue);
     void fetch().then((r) => { if (!cancelled) setData(r); });
     return () => { cancelled = true; };
   }, [key]);
   ```
   Live in [`InspectorHub.tsx PresetStrip`](file:///Volumes/Projects/Development_Projects/Github_Repos/element/webview/src/components/layout/InspectorHub.tsx) lines ~81-92.
