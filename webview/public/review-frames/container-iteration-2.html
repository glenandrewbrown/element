S8c — Motion intent (no animation in file)
Intended live behaviour

Cable shimmer: active cables in the thumbnail animate a travelling dash-offset at ~1.5 s/cycle using stroke-dasharray + stroke-dashoffset CSS animation. Only cables with live signal; idle cables remain static.

Header VU bars: 4 mini bars in the header animate height from requestAnimationFrame driven by the block's peak RMS. Bars are 3 px wide, 12 px tall max. Only while audio is flowing.

Thumbnail border pulse: a 1 px border fades between rgba(74,144,217,0.0) and rgba(74,144,217,0.3) on a 2 s ease-in-out loop when signal is present. Stops on silence after 500 ms.

Design rationale + open questions for Glen
S1 — Standard 96 px (idle/hover/selected)
Idle keeps cable opacity low so the thumbnail reads as a schematic, not noise. Hover brightens cables and the dive hint simultaneously — the two cues reinforce each other. Selected swaps the icon stroke to the instrument colour and adds a 1.5 px ring at 25 % glow; the selection signal comes from the ring, not from filling the whole block with colour.
S2 — Compact / title tiers
Three discrete breakpoints driven by zoom level: micro-strip (dots only, no labels) at ~0.45×, count chip in the header at ~0.35×, icon-only at ~0.20×. The count chip is purely typographic — no thumbnail DOM at all, so no layout cost. The icon tier drops even the IO label; only port pips remain for cable-drag affordance.
S3 — Dense fallback (>12 blocks)
Above 12 internal blocks the mini-graph becomes unreadable pixel noise. The heatmap replaces it: each bar is one block, coloured by category, height proportional to the block's output port count (as a rough complexity proxy). The threshold note is always shown so the user understands the switch. At-threshold specimen (S3b) shows the mini-graph is still usable at 12 — the cutoff is intentionally generous.
S4 — Portal vs Container
Local Container uses a neutral "Local" badge and the standard white icon. Portal uses a teal accent throughout (header line, icon arrow, badge, LED) and a dashed outline on the thumbnail — dashes signal "externally linked" without explaining it in text. The filename path row is a secondary cue. Missing-file state (S4c) escalates to a red ring + warning icon — the thumbnail region becomes an error surface with a right-click instruction.
S5 — Muted / Bypassed
Muted: red ring (1.5 px, 55 % opacity) + filter:saturate(0.15) brightness(0.65) on the thumbnail. The saturation drop is the visual key — colour is the information medium, so draining it communicates "this isn't contributing." Bypassed: grey ring only + full desaturation (saturate(0)) + a "signal passes through" hint row. Bypassed is visually quieter than muted because it's the safer state.
S6 — IO summary lanes
IN/OUT bars sit flush above and below the thumbnail, sharing its inset shadow — they read as part of the same recessed panel, not separate controls. Multi-signal (S6b) uses the pip shape vocabulary from the rest of the system: circle = audio, triangle-fill = MIDI, rotated square = CV. The bars are purely informational; they don't add interactive affordance.
S7 — Nested container in thumbnail
The nested container is a bordered rectangle inside the thumbnail with its own mini icon and a tiny node row. It deliberately looks like a block-inside-a-block — the visual metaphor is recursive without needing text. The depth badge switches to "N levels deep" when nesting is detected. The outer dive hint still says "double-click to enter" (entering the outer container, not the inner one).
S8 — Activity hint
Static mock shows two states: idle (low-opacity cables, dim LED) and active (cables at full intensity + a 4-bar VU strip in the header + a soft outer glow on the block). The motion intent note documents the three animation layers — cable dash-offset, VU bars via rAF, thumbnail border pulse — so Glen can judge cost vs value before any animation code is written. The intent is that all three cues switch off when the block is silent.
Open questions for Glen
Density threshold at 12 blocks: does this feel right for typical sessions, or should it be lower (e.g. 8) to keep the thumbnail uncluttered earlier?
Portal dashed-outline: clear enough to distinguish from Container at a glance, or would a different colour (e.g. teal fill strip on the thumbnail top edge) be stronger?
Activity hint: are all three motion layers (cable shimmer + VU bars + border pulse) wanted, or should only one cue be used to avoid visual noise during playback?
Recommendation: Ship S1 (idle/hover/selected) + S2 (compact tiers) + S5 (muted/bypassed) as the first implementation slice — these cover the everyday editing states. Add S4 (Portal) and S6 (IO lanes) in the same pass since they reuse existing CSS classes. S3 (dense fallback) and S7 (nested visible) can follow once the mini-graph renderer is stable. S8 activity hints should wait for a deliberate motion pass so the rAF budget is evaluated with real audio running.
