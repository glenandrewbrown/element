## §2 — PROJECT MENTAL MODEL (read this before touching code)

Element is a JUCE 8 / C++20 audio plugin host. The standalone app loads two parallel UI shells:

1. **WebContent (default — V3.0 React/Tailwind shell)** — `webview/dist/index.html` rendered in JUCE's `WebBrowserComponent`. Communicates with C++ via `window.__JUCE__.backend.invokeNativeFunction(name, args)`.
2. **StandardContent (legacy native — `ELEMENT_STANDARD_CONTENT=1`)** — pre-V3.0 JUCE-native UI; functionally complete, source of truth for what features should exist.

```
Application (src/application.cpp)
└── Context (src/context.cpp) — DI container
    ├── AudioEngine (src/engine/audioengine.cpp) — graph + I/O
    ├── PluginManager (src/pluginmanager.cpp) — discovery
    ├── MidiEngine (src/engine/midiengine.cpp)
    ├── ScriptingEngine (Lua via sol2)
    ├── DeviceManager
    ├── MappingEngine
    └── Services (Device, Engine, Gui, Mapping, Osc, Preset, Session)

PluginEditor (src/plugineditor.cpp) → AudioProcessorEditor + AsyncUpdater
PluginProcessor (src/pluginprocessor.cpp) → format adapter (VST3/AU/CLAP/LV2)

WebView pipeline:
  WebContent (src/ui/web_content.cpp) → ElementWebViewHost (src/ui/element_webview_host.cpp)
   → JUCE WebBrowserComponent → WKWebView (macOS)
   → Loads webview/dist/index.html
   ← JS calls invokeElementNative(name, args)
   ← JS subscribes to event channels (onGraphState 60Hz, onMetering, etc.)
```

**Key fact:** the UI you actually see is React. The native (StandardContent) UI is the reference for what the React UI **should** mirror. A/B comparison is the canonical bug-discovery method.

## §4 — ENGINE-SNAPSHOT ARCHITECTURE (the dominant fix pattern — replicate this)

This pattern was introduced this session and is the canonical way to surface live engine state in React. Use it for any new status display.

### C++ side — bridge handler emits a JSON snapshot

`src/ui/element_webview_host.cpp:885-958` registers `elementGetEngineSnapshot`:

```cpp
registerFn (
    Identifier ("elementGetEngineSnapshot"),
    [this, postCompletion] (const Array<var>&, auto completion) {
        DynamicObject::Ptr snapshot = new DynamicObject();
        snapshot->setProperty ("cpu", context.devices().getCpuUsage());
        snapshot->setProperty ("sampleRate", setup.sampleRate);
        snapshot->setProperty ("bufferSize", setup.bufferSize);
        snapshot->setProperty ("deviceName", deviceName);
        snapshot->setProperty ("deviceLatencyInputMs", inputLatencyMs);
        snapshot->setProperty ("deviceLatencyOutputMs", outputLatencyMs);
        snapshot->setProperty ("engineRunning", engineRunning);
        snapshot->setProperty ("transportPlaying", transportPlaying);
        snapshot->setProperty ("transportRecording", transportRecording);
        snapshot->setProperty ("tempoBpm", tempoBpm);
        snapshot->setProperty ("timeSig", timeSigArray);
        snapshot->setProperty ("transportTimecode", timecodeStr);
        postCompletion (completion, JSON::toString (var (snapshot.get())));
    });
```

Runs on JUCE message thread. Reads atomic-published or message-thread-safe values only.

### React side — typed wrapper + Zustand store + selectors

`webview/src/bridge/nativeEngineSnapshot.ts` — typed parser around `invokeElementNative("elementGetEngineSnapshot", [])` with safe defaults if the bridge returns nothing.

`webview/src/stores/useEngineSnapshotStore.ts` — Zustand store with `startPolling(intervalMs)` / `stopPolling()` lifecycle and per-field selectors:
```ts
selectCpuPercent, selectSampleRate, selectBufferSize,
selectDeviceName, selectDeviceLatencyMs, selectEngineRunning,
selectTransportPlaying, selectTransportRecording,
selectTempoBpm, selectTimeSig, selectTransportTimecode
```

Polling default: **250 ms (4 Hz)**. Architect noted this is below the PRD-stated 10-30 Hz target; functionally adequate, worth tracking as a follow-up.

### Consumer pattern — subscribe via selector

```tsx
import { useEngineSnapshotStore, selectCpuPercent } from "../../stores/useEngineSnapshotStore";

export function MyStatusDisplay() {
  const cpu = useEngineSnapshotStore(selectCpuPercent);
  return <span>{cpu.toFixed(1)}%</span>;
}
```

Wired consumers at handover:
- `webview/src/components/layout/StatusBar.tsx` — engineRunning, CPU, sample rate, buffer
- `webview/src/components/layout/InspectorHub.tsx` PROJECT OVERVIEW — TOTAL CPU, HOST CPU, SAMPLE RATE, BUFFER, DEVICE LATENCY, DEVICE
- `webview/src/components/layout/Toolbar.tsx` — Record button, Play/Pause icon

### When NOT to use this pattern

- For graph topology (block list, cable list) — use the existing `onGraphState` 60 Hz push channel via `useGraphStore`. The engine snapshot is for engine *state*, not graph *structure*.
- For per-block parameters — use `elementGetNodeParameters` with a node UUID. (Per-block CPU + latency now ride the graph snapshot at `webview/src/hooks/useJuceBridge.ts:202-209` since `9ba350bc`.)
