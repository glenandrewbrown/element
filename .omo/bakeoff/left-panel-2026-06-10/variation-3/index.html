VARIATION 3 — COMPACT GRID + LIST TOGGLE
The only variation that offers a grid card view. Three cards wide at 260px. Best for visual browsers who recognise plugin names by card identity rather than reading a list. Toggle between grid and list from the header — persistent per-session.
Grid cards — neumorphic raised surfaces
Each card is a raised neumorphic surface with a 2px accent top strip (category colour). The category shape glyph is large (22px) for instant visual recognition. Hover reveals the drag handle (⠿) bottom-right.
Auto sub-grouping within category
Section dividers (Synthesizers / Samplers / Organs) appear when a category is filtered — auto-derived from BrowserPlugin.tags. In unfiltered All view, sections are hidden; the grid is a flat sorted list.
List mode = search-optimised
When the user types a query, the view auto-switches to list mode for denser results (28px rows vs 64px cards). The user can override back to grid. This mirrors how Finder switches to list on search.
Trade-offs vs V1
Grid shows ~12 plugins in the viewport vs V1's ~18 list rows. Lower density. But for users who browse by recognition rather than name, the card identity is faster than reading a list. Appropriate if Glen frequently browses with a category filter applied.
Component mapping
New PluginCard component (already exists in palette/PluginCard.tsx for the grid variant). View toggle stored in useAppStore. Auto-switch to list on search needs a useEffect in ToolPalette watching the search field.
