VARIATION 2 — CATEGORY-LED
Two-column: a fixed category nav rail on the left drives what the list pane on the right shows. Category identity is always visible. Good for users who think in plugin type rather than name.
Category rail = persistent context
The 52px rail shows all 4 categories + ★ Fav + ⏱ Recent at all times. The active accent bar on the left edge mirrors the canvas block shape colour. No tab strip needed — the rail IS the tab strip, always visible.
Vendor sub-grouping within category
Inside Audio FX (147 plugins), dividers group by sub-type (EQ / Compression / Reverb…). This is auto-derived from the existing BrowserPlugin.tags field — no new data required. Sub-groups only appear when the list > 12 items.
Inline ★ favourite toggle
Each row has a ★ that lights amber on hover/tap. No separate section needed. PluginUsageTracker already tracks favourites — this just surfaces the toggle directly in the row.
Width trade-off
Panel is 280px (20px wider than V1's 260px) to accommodate the 52px rail + readable list. Consider this against screen real estate. The rail can collapse to icons-only at 36px if the category names are dropped.
vs Variation 1
V1 is faster for search-by-name (one field, one list). V2 is faster for category-browsing (tap ◆, skim sub-groups). If Glen mostly searches by name → V1. If Glen mostly browses by category type → V2. The brief suggests search-first users dominate.
